# ツイッ棚（TwitTana）第1弾 設計書

- 作成: 2026-10-02
- 状態: ユーザー合意済みの方針をまとめたもの（エラー時の動き・テストは「おすすめで進めてよい」の指示に基づき決定）

## 1. 目的と成功の条件

Twitter（現 X）のブックマークが放り込みっぱなしになる問題を解く。自分で作ったフォルダに振り分け、あとで見返せるようにする。

成功の条件:

- 無料の X アカウントで使える（X Premium のフォルダ機能に頼らない）
- 運用費 0 円（サーバーを持たない）
- ブクマした投稿が、その場で、またはあとからまとめて、フォルダに入る
- ルールと AI で「未整理」が自然に減る
- 「今日の積みツイ崩し」で、毎日少しずつ過去のブクマを見返せる
- Chrome ウェブストアの審査を通る

## 2. 前提と制約

調査（2026-10-02）で分かったことと、そこから決めた制約。

| 事実 | 決めたこと |
|---|---|
| X API は無料枠なしの従量課金で、開発者が払う。ブクマは最新 800 件まで | X API は使わない |
| X の規約は書面同意のないスクレイピング・クローリングを禁止 | 拡張から X へ自分でリクエストを送らない。X の画面が受け取ったデータを横で読むだけ。自動スクロール・自動クリックもしない |
| X 社は「Twitter」の商標を保持・行使中（2026-09 に米国で他社の使用差し止め） | 名前・アイコンに「Twitter」単体や X のロゴを使わない。説明文で「Twitter（現 X）」と書くのは可。「非公式」を明記 |
| Chrome ウェブストアの規約で AdSense は拡張に使えない | 拡張の画面に広告を入れない。収益は寄付リンクと、将来の紹介サイトの広告 |
| Chrome 内蔵 AI（Gemini Nano / Prompt API）は拡張から無料で使え、日本語に対応。ただし PC の要件が高い | AI 分類は「使える PC だけのおまけ」。使えない PC でもルールで振り分けられる |
| X のブクマ画面は最新 800〜1,000 件ほどまでしか遡れないという報告がある | 取り込んだ投稿は、X で解除されても拡張の中に残す |

## 3. 段階

| 段階 | 内容 |
|---|---|
| **第1弾（この設計書）** | PC の Chrome 拡張。スマホでブクマ → PC で整理・見返し、の流れも成り立つ |
| 第2弾 | スマホ用 Web アプリ（X アプリの共有ボタン → フォルダ選択。投稿の中身は X の oEmbed で取得。iPhone は共有先に出せないので手間が増える） |
| 第3弾 | PC とスマホの同期（Cloudflare の無料枠の見込み） |

第2弾で作り直しにならないよう、X に依存しないロジックとデータの形は `src/core/` に分けておく。

## 4. 第1弾の機能範囲

入れるもの:

- **取り込み**: X のブクマ画面をスクロールした分をまとめて／タイムラインなどでブクマした投稿をその場で。画像は URL だけ保存
- **フォルダ**: 作成・名前変更・削除・並べ替え・説明（AI 向けのヒント）。入れ子なし。1 投稿を複数フォルダに入れられる。どこにも入っていないものは「未整理」
- **振り分け**: ブクマした瞬間に小さなメニューでフォルダを選ぶ（設定でオフ可）／本棚画面で複数選んでまとめて入れる・外す
- **自動振り分け（ルール）**: 本文のキーワード・投稿者・ハッシュタグ・リンク先のドメイン・画像や動画あり。取り込み時に自動適用＋「未整理に今すぐ適用」
- **AI 分類**: Chrome 内蔵 AI がフォルダの中から選ぶ。本棚画面を開いている間に未整理を順番に処理
- **今日の積みツイ崩し**: 毎日 N 件（初期 5）の過去のブクマを出す。拡張アイコンに残り件数
- **本棚画面**: フォルダ別一覧・キーワード検索・並び順（取り込み順／投稿日）・クリックで元投稿を開く・「AI が入れたもの」「解除済み」での絞り込み
- **X でブクマを外したら**: 拡張には残し「解除済み」の印
- **その他**: JSON の書き出し・読み込み、日本語と英語、設定画面に寄付リンク、ストア掲載用のプライバシーポリシーページ

入れないもの（あとで）: フォルダの入れ子・メモ・色分け、画像の保存、Markdown / CSV 書き出し、Firefox 版、スマホ版、同期、紹介サイト。

対応ブラウザ: Chrome と Edge（同じパッケージ）。

## 5. 技術構成

| 用途 | 道具 |
|---|---|
| 拡張の土台 | WXT（Manifest V3。Chrome / Edge / Firefox 向けに出せる） |
| 言語・画面 | TypeScript ＋ React ＋ Tailwind |
| 保存 | IndexedDB ＋ Dexie |
| テスト | Vitest（IndexedDB は fake-indexeddb で代用） |

## 6. 部品と役割

```
x.com のページ
 ├─ [取り込み係]  MAIN world の content script（document_start）
 │     X の画面の通信の返事を横で読み、読み取り係で投稿に変換
 │     直前に見た投稿を数百件だけ覚えておく
 │        │ window.postMessage（形を検査してから受け取る）
 │        ▼
 ├─ [橋渡し係]  通常の content script
 │     裏方へ中継／フォルダ選択メニュー／ブクマ画面の「N件取り込み済み」表示
 │        │ runtime メッセージ
 ▼        ▼
[裏方]  background（service worker）
   保存（Dexie）・ルール適用・アイコンの件数表示・本棚画面を開く
        ▲
        │ 同じ Dexie を直接読み書きする（拡張の中なので同じ保存場所）
[本棚画面]  拡張の専用ページ（React）
   一覧・検索・今日の積みツイ崩し・フォルダ／ルール編集・設定・書き出し・AI 分類
```

| 部品 | 置き場所（予定） | 役割 | 依存 |
|---|---|---|---|
| データの形・ルール判定・見返しの選び方・AI への指示文・書き出し形式 | `src/core/` | X にもブラウザにも依存しない純粋なロジック。第2弾でも使う | なし |
| 読み取り係 | `src/x/` | X の通信データ → `Post`。**X の仕様変更で壊れるのはここだけにする** | `core` |
| 保存の窓口 | `src/db/` | Dexie の表定義と、保存・取得の関数 | `core` |
| 取り込み係・橋渡し係・裏方・本棚画面 | `entrypoints/`（WXT の入口） | 上の図のとおり | 上の 3 つ |
| 画面部品 | `src/ui/` | 本棚画面とメニューで使う React 部品 | `core` |
| 文言 | `locales/`（ja / en） | 画面の文言 | なし |

## 7. データの形

```ts
type Post = {
  id: string;                  // X の投稿 ID
  url: string;
  text: string;
  author: { id: string; handle: string; name: string; avatarUrl: string };
  postedAt: string;            // ISO 8601
  media: { type: "photo" | "video" | "gif"; url: string; thumbUrl: string }[];
  links: { url: string; domain: string }[];   // 展開後の URL
  hashtags: string[];
  quoted?: { id: string; authorHandle: string; text: string };
  capturedAt: string;          // ツイッ棚に入った日時
  bookmarkOrder?: string;      // X のブクマ一覧での並び（新しいほど大きい）。並べ替え用
  folders: { folderId: string; by: "manual" | "rule" | "ai" }[];
  removedOnX: boolean;         // X でブクマ解除済み
  hidden: boolean;             // 「もう出さない」
  aiCheckedFoldersVersion?: number; // この版のフォルダ構成で AI が判定済み
  review: { count: number; lastAt?: string };
};

type Folder = { id: string; name: string; description: string; order: number; createdAt: string };

type Condition =
  | { kind: "keyword"; value: string }
  | { kind: "author"; handle: string }
  | { kind: "hashtag"; tag: string }
  | { kind: "domain"; domain: string }
  | { kind: "hasMedia"; media: "any" | "photo" | "video" };

type Rule = { id: string; folderId: string; conditions: Condition[]; enabled: boolean; order: number };

type Settings = {
  pickerOnBookmark: boolean;   // 初期 true
  aiEnabled: boolean;          // 初期 false（準備ボタンで true）
  language: "auto" | "ja" | "en";
  reviewPerDay: number;        // 初期 5
  foldersVersion: number;      // フォルダの追加・削除・改名・説明変更で +1
  todayReview?: { date: string; postIds: string[]; doneIds: string[] };
  parseHealth: { lastOkAt?: string; lastErrorAt?: string; lastErrorOp?: string };
};
```

- 投稿・フォルダ・ルール・設定はすべて Dexie に置く。x.com のページ内の部品（メニューの表示有無など）は、裏方に問い合わせて設定を得る
- 1 件あたり数 KB。1 万件でも数十 MB に収まる。`unlimitedStorage` 権限で容量の上限を気にしなくてよくする
- 投稿の保存は「上書き合流」: 既にある投稿は本文などを新しい値で更新し、`folders`・`hidden`・`review` は保つ。ブクマ画面で再び見えたら `removedOnX = false`

## 8. 取り込みの流れ

1. 取り込み係は `fetch` と `XMLHttpRequest` を包み、パスが `/i/api/graphql/<id>/<操作名>` の返事だけを複製して読む。X の画面へ渡す元の返事には一切手を加えない
2. 返事の JSON から投稿のかたまり（`__typename` が `Tweet` のもの、`TweetWithVisibilityResults` の中身を含む）を再帰的に探して `Post` に変換する。操作名の一覧に頼りすぎず、形で探すことで X の変更に強くする
3. 操作名がブクマ一覧（`Bookmarks`、`BookmarkSearchTimeline`、`BookmarkFolderTimeline` など `Bookmark` で始まる一覧）なら → 橋渡し係経由で裏方に保存させる（`bookmarkOrder` は一覧の各項目の並び値 `sortIndex` から。数字の文字列なので比較は桁をそろえて行う）
4. それ以外（タイムライン・検索・個別投稿など）なら → 保存せず、直前の 500 件を覚えるだけ（古いものから捨てる）
5. ブクマ追加の通信（`CreateBookmark`）を見たら、送られた投稿 ID で覚えている投稿を探して保存し、フォルダ選択メニューを出す。見つからなければ、画面に表示中の投稿から本文などを読む（`src/x/` の画面読み取り）
6. ブクマ解除の通信（`DeleteBookmark`）を見たら、`removedOnX = true` にする
7. DM など投稿以外のデータは読まない
8. 保存は必ず裏方が行う。x.com のページ内からは拡張の IndexedDB に書けないため
9. 保存されたら、ルールを当てる（9 章）

ブクマ画面では、右下に小さく「ツイッ棚：N 件取り込み済み」を出す。

## 9. 振り分け

優先順位は **手動 ＞ ルール ＞ AI**。手動で入れた投稿には、ルールも AI も手を出さない。

### 手動

- ブクマした瞬間: ブクマボタンの近くに、フォルダ一覧のメニュー（Shadow DOM で X の見た目と隔離）。押すたびにそのフォルダへの出し入れをすぐ保存（複数選べる）。「新しいフォルダ」も作れる。8 秒操作がなければ自動で閉じる（何も選ばなければルール・AI に任せる）。ボタンの位置が分からないときは画面右下に出す
- 本棚画面: 複数選んで、まとめて入れる・外す

### ルール

- 1 つのルールの中の条件は**すべて**満たしたら当てはまる。同じフォルダに複数のルールがあれば、**どれか**に当てはまれば入る
- 文字の比較は、NFKC で正規化して大文字小文字を区別しない（全角半角の違いを吸収）
- 取り込み時に、手動の振り分けがない投稿へ自動で当てる
- 「未整理に今すぐ適用」で、どのフォルダにも入っていない投稿へまとめて当てる
- 第1弾では、ルールを変えても既に入れたものは外さない（足すだけ）

### AI

- Chrome 内蔵 AI は画面を持つページからしか使えないので、**本棚画面を開いている間**に処理する（裏方からは呼べない）
- 対象: どのフォルダにも入っておらず、非表示でなく、`aiCheckedFoldersVersion` が今の `foldersVersion` と違う投稿。古い順ではなく新しい取り込み順に 1 件ずつ
- 準備: 設定の「AI を準備する」ボタン（Chrome の決まりで、モデルのダウンロード開始には利用者の操作が要る）。進み具合を表示。要件を満たさない PC では「このPCでは AI 分類は使えません。ルールは使えます」と表示し、AI の項目を隠す
- 指示文: フォルダ名と説明の一覧、フォルダごとに手動で入れた例を最大 2 件（本文は短く切る）、対象の投稿（本文は 500 字まで、投稿者、ハッシュタグ、リンク先ドメイン）。入りきらないときは例から削る
- 返事の形は JSON Schema で制限する: `{ folder: <フォルダ名のどれか> | "none", confidence: "high" | "low" }`。`high` のときだけ入れる（`by: "ai"`）。それ以外は未整理のまま
- 判定した投稿には `aiCheckedFoldersVersion` を記録し、フォルダ構成が変わるまで再判定しない
- 本棚画面に「未整理を AI で振り分け」ボタンと、処理中の件数を出す。AI が入れたものには「AI」の印

## 10. 今日の積みツイ崩し

- 選び方（`src/core/` の純粋関数。日付を種にした乱数で、同じ日は同じ結果）:
  1. 非表示を除く
  2. 一度も見返していない投稿を、ブクマの古い順（`bookmarkOrder`、無ければ `capturedAt`）に最大 50 件取り、その中から乱数で N 件
  3. 足りなければ、見返した日時が古い順に足す
- その日の顔ぶれは `todayReview` に保存し、日付が変わったら選び直す
- 1 件ごとの操作: 「見た」／「フォルダへ入れる」／「もう出さない」（`hidden = true`。消すと X のブクマ画面でまた取り込まれるため印にする）。どれをしても「済み」になり `review` を更新
- 拡張アイコンに残り件数を表示（0 なら消す）。通知の権限は使わない
- 件数の計算と日付の切り替えは裏方が行う。タイミングは、Chrome の起動時・x.com からの取り込み時・本棚画面を開いたとき（定期実行の権限は使わない）

## 11. 本棚画面

- 拡張アイコンを押すと、本棚画面を新しいタブで開く（既に開いていればそこへ移る）
- 左: 「今日の積みツイ崩し」「すべて」「未整理」「AI が入れたもの」「解除済み」、その下にフォルダ一覧（並べ替え可）
- 上: 今日の積みツイ崩しのカード列（残りがあるとき）、検索欄、並び順（ブクマ順＝`bookmarkOrder`、無ければ `capturedAt`／投稿日。それぞれ新しい順・古い順）
- 中央: 投稿カード（アイコン・表示名・@名・本文・画像の縮小表示・投稿日・入っているフォルダ）。クリックで元投稿を X で開く。複数選択でまとめて操作
- 別タブ: フォルダとルールの編集、設定（ブクマ時メニュー・AI・言語・1 日の件数・書き出し／読み込み・寄付リンク・プライバシーポリシー）
- 検索は本文・表示名・@名の部分一致（NFKC 正規化）。1 万件程度なら全件走査で足りる

## 12. 書き出し・言語・権限・プライバシー

- 書き出し: `{ app: "twittana", schemaVersion: 1, exportedAt, folders, rules, posts }` の JSON。設定は含めない
- 読み込み: `app` と `schemaVersion` を確かめ、形が違えば理由を出して中止。投稿は上書き合流（フォルダは足し合わせ）、フォルダ・ルールは ID で合流
- 言語: 日本語と英語。初期はブラウザの言語に合わせる
- 権限: `unlimitedStorage` と、ホスト権限 `https://x.com/*` だけ
- 通信: 拡張は外部サーバーへ何も送らない。本棚画面で画像を表示するときに X の画像配信（`pbs.twimg.com` など）から読み込むだけ
- プライバシーポリシー: 上の内容を日本語と英語で書き、GitHub Pages で公開してストアに載せる

## 13. エラー時の動き

| 場面 | 動き |
|---|---|
| X の仕様が変わって読み取りに失敗 | X の画面は壊さない（取り込み係の処理はすべて例外を握りつぶし、元の通信はそのまま流す）。`parseHealth` に記録し、ブクマ画面の表示と本棚画面に「X の仕様が変わったようです。更新をお待ちください」と出す。外部への送信はしない |
| ブクマ押下時に投稿が見つからない | 画面の表示から読む。それも失敗したら ID と URL だけ保存し、次にブクマ画面で見えたときに中身を埋める |
| 裏方が眠っていて返事がない | 橋渡し係が少し待って再送（最大 3 回）。だめなら次の機会の再送用に、ページ内に一時的にためる |
| 保存の失敗（容量など） | 本棚画面に理由を出し、書き出しでの退避を勧める |
| 読み込みファイルが不正 | 何も変えずに中止し、理由を出す |
| AI の準備失敗・途中のエラー | その投稿は飛ばして未整理のまま。5 件続けて失敗したら止め、理由を出す |
| フォルダの削除 | 確認を出す。投稿からそのフォルダを外し（どこにも無くなれば未整理）、そのフォルダ宛てのルールも消す |
| データの形を変えるとき | Dexie の版を上げ、移行処理を書く。書き出しの `schemaVersion` も上げる |

## 14. テスト

- **自動テスト（Vitest）**: `src/core/`（ルール判定・見返しの選び方・AI 指示文の組み立てと返事の解釈・書き出し形式の検査）、`src/x/`（読み取り係）、`src/db/`（fake-indexeddb で保存の合流・フォルダ削除など）
- **読み取り係のテスト用データ**: 開発版だけにある「生データを保存」スイッチで X の返事を保存し、匿名化スクリプトで名前・本文・ID・URL を置き換えてから `tests/fixtures/x/` に置く。**リポジトリは公開なので、匿名化前のデータは絶対にコミットしない**
- **実際の X での確認**: 自動化（ログインの自動操作）はしない。`docs/manual-test.md` の確認表（ブクマ画面の取り込み、タイムラインでのブクマとメニュー、解除、ルール、AI、積みツイ崩し、書き出し・読み込み）を、公開前とリリースごとに手で回す
- 変更のたびに `npm test` と型チェック、lint を通す
